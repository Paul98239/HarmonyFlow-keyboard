# CLAUDE.md

本檔只在處理 `test/` 底下的檔案時載入，說明自動化測試怎麼跑、各測試涵蓋什麼與已知限制；專案整體規則見根目錄 `CLAUDE.md`。

- **自動化測試**：`playwright` 是 `package.json` 的 devDependency，先 `npm install`；`test/` 底下的腳本只服務開發／測試，不影響 app 本身零建置、直接從 CDN 匯入相依套件的部署方式。兩類測試：
  - `test/browser/smoke-test.mjs`（`node test/browser/smoke-test.mjs` 執行）：用 Playwright 開真的 Chromium＋假攝影機輸入，跑過選人數／載入本地樣本樂譜／指派聲部／按播放、暫停、重播整條流程，以及試聽（♪）的整條流程（進出試聽、暫停／續播／重播、播完、載入中換歌的 race、壞檔與引擎壞掉的錯誤路徑、試聽 vs 演奏互斥），鍵盤觸發（四排字元鍵觸發演奏者 1；按住不放、Ctrl／Alt 組合鍵、不在四排的鍵、搜尋欄打字都不觸發；焦點在下拉時 type-ahead 被擋掉，用臨時下拉驗證，拿掉 `preventDefault()` 會變紅），含播放列四顆按鈕在各狀態下的灰亮與黃底、64 種 store 組合的窮舉（對照獨立寫的期望表，灰掉的按鈕被 action 直接呼叫也必須是 no-op），檢查過程中有沒有非預期的 console error／warning／pageerror（錯誤路徑測試預期的 warn 用 `expectConsole()` 白名單，而且要斷言它真的出現）；worklet 內部狀態用「回讀」驗證——合成器實例就是 `humanPerformer.assistSynth`／`humanSynth`，主執行緒的 `midiChannels[i].patch` 與 `eventHandler` 的 programChange／controllerChange／noteOn 事件是 worklet 回報的狀態：目前驗證各 channel 的打擊配置，以及載入 MuseScore 形狀的譜整首自動播放時，每個 voice 的 program 與 CC7／10／91／93 在第一個 noteOn 之前真的到了 worklet、值等於排程器送出去的。寫新的 `page.waitForFunction()` 判斷式必須是**同步**函式：async 函式回傳的 Promise 本身永遠 truthy，Playwright 會當成條件立刻成立、等於沒等（測試頁面把 store／synth 掛在 `window.__hf` 供同步讀取）。**這個測試看不到 `spessasynth_processor.min.js`（AudioWorkletProcessor，音訊渲染執行緒）丟出的例外**：已實測確認，即使刻意讓 worklet 端丟出 Uncaught TypeError，`page.on('console')`／`page.on('pageerror')` 都收不到任何訊號，測試照樣回報「沒有問題」。牽涉 spessasynth worklet 內部狀態的 bug（例如 channel 配置、bank／program 是否真的送達）不能只靠這個測試「沒有報錯」判斷有沒有解決，要用直接印值驗證（`console.log` 搭配 `setTimeout` 讓非同步的 worklet 訊息先處理完再讀取狀態）。
  - `test/unit/*.test.mjs`（`node test/unit/midi-parser.test.mjs`、`node test/unit/human-performer.test.mjs`、`node test/unit/midi-api.test.mjs`、`node test/unit/preview-player.test.mjs`、`node test/unit/playability.test.mjs`、`node test/unit/oracle.test.mjs` 各自執行，純 Node，不需要瀏覽器）：對 `midiParser.js`／`humanPerformer.js`／`previewPlayer.js`／`midiApi.js` 這類純邏輯模組直接跑回歸測試，`preview-player.test.mjs` 用假的 Sequencer 測官方載入結果的等待（同名 songChange 才算、midiError、逾時、被中斷／換歌、事件監聽不累積、播完從頭）；`playability.test.mjs` 定義並驗證「解析後的檔案可以播放」——用嚴格的假合成器（channel 0～63、打擊槽 9／25／41／57 只給打擊 voice、初始狀態 bank／program／CC7／10／91／93 先於第一個 noteOn、值域、每個 noteOn 一個 noteOff、沒有卡音、指派聲部沒被揮過手不出聲；違規只記錄、跑完統一檢查，因為排程器對合成器的呼叫包在 try／catch 裡）對 canon 樣本與手工組的 MuseScore 形狀譜（鋼琴兩行譜、弓弦含 pizzicato、打擊）跑整首自動播放與兩位演奏者的腳本化手勢；涵蓋 SMF 解析的邊界情況（program 依時間軸查詢、running status 寬鬆讀取）與聲部切分（鋼琴兩行譜併成一個 part 兩個 voice、弓弦的 pizzicato channel、Meta 軌佈局、〈蝸牛與黃鸝鳥〉＝長笛＋大鋼琴的金標準結構、port 絕對 channel、同音高重疊警告、命名與同名序號）、排程器的核心行為（單一樂譜時鐘與一次放行一拍、揮手比時鐘早的追趕、揮手間隔的速度估計與時鐘／代打／合併窗跟著速度走、前奏、先進先出收音、相連音撐住與停格釋放、dt 上限、多人合併窗與路過的拍、代打補位（含有音符的拍）、遲到揮手歸屬與合奏層級倒數、取樣離群暫存、自動終局、重設／重播、代打音量對比，以及固定種子的整體不變量壓力測試）與雲端下載連結 log。沒有測試框架，跟 smoke-test.mjs 同一套 `run()`／`assert()` 手寫慣例。`oracle.test.mjs` 是**差異測試**：用 devDependency `spessasynth_core`（版本釘住，`npm install` 後可用；app 本身仍走 CDN、不受影響）的官方 `SpessaSynthSequencer` 當標尺，把 processor 的 noteOn／noteOff／programChange／controllerChange 換成記錄器（不載音色庫、不出聲），取得「官方播放器實際送給合成器的事件」，再跟 `parseMidi()`（L1）、排程器整首自動播放與被完美演奏者驅動時發出的音（L2）、以及「同一樂譜時刻的音要同時」的同步不變量（L3）比對。`runKnownDiff()` 標記目前已知有差異的項目（附原因），它驗證「差異確實還在」，差異消失時會反過來失敗，提醒改成 `run()`；目前沒有已知差異（同 tick 的速度衝突與 port 絕對 channel 都已跟官方一致）。smoke test 開頭會印出 CDN 上官方套件版本，跟 devDependency 不同時提醒（標尺可能落後於 app 實際載入的版本）。
  - `test/tools/`（手動執行，不進 CI）：`library-scan.mjs` 用整個遠端 MIDI 曲庫驗證 parser 與排程器——解析與聲部切分（沒有例外、每個 voice 分得到輸出 channel、警告分類、多聲部可指派的歌有幾首、〈蝸牛與黃鸝鳥〉＝長笛＋大鋼琴的金標準）、整首自動播放的忠實度、多聲部歌曲 × 3 種揮手風格、多人／晚進場／停手回來／漏揮與速度（×0.7～×1.6、漸快漸慢、突然變速）等情境，另量揮手→發聲的延遲、電腦搶在揮手前放行的比例、漏揮補位的時間差，以及共用拍位有沒有比演奏者數的拍多走；情境掃描帶量化門檻（穩定揮手抖動 ±15％ 時電腦搶先 ≤5％、共用拍位不多走、漏揮補位 ≤0.35 拍、前奏打拍子時前奏的音與樂譜時間差 ≤60ms），不達標算不符合，已知未達標的情境（慢 ×1.25／×1.6、突然變慢、漏揮 30％）標 ⚠ 與原因照樣印出、不算不符合（`known` 欄位，修好就移掉）（`--download` 把曲庫抓到 `test/tools/library/`，不進 git；`--only=parse,autoplay,perform,scenarios` 選掃描）；`sim.mjs` 是它用的模擬演奏者與量測；`jitter-measure.mjs` 在真的 Chromium 裡量主執行緒排程器的抖動（`humanPerformer.tick` 的間隔、超過 25／50／100ms 的比例、noteOn 到 worklet 回報的來回延遲、長任務），分「鏡頭開未選人數」「現場人數＝1」「鏡頭關閉」三階段對照，用來分辨抖動來自影像算繪還是姿勢推論；無頭軟體算繪的數字不能直接當使用者機器的數字，要比較就在同一台機器前後各量一次（`--seconds=N`、`--midi=檔案`）；`mutation-check.mjs` 在暫存資料夾裡故意把排程器、`midiParser.js` 的聲部切分、`previewPlayer.js` 弄壞（一次一行），確認指定的測試會變紅；`target` 欄位可以指定破壞別的檔，`suites` 含 `'smoke'` 的變異改用瀏覽器測試抓（`HF_ROOT` 指向被破壞的複本，每個要一分多鐘；`--skip-smoke`／`--only-smoke` 選快的或慢的一半）。
